# Развёртывание сайта

Сайт работает в публичном режиме: `STRAZH_MODE=public`. Каждый посетитель получает свою комнату в памяти, владелец
входит паролем в основную комнату, где подключён Telegram.

## Render, бесплатный тариф

### Кнопкой, без передачи ключей

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/mess1ahbenz/strazh-invest)

1. Нажмите кнопку и войдите в Render (можно через GitHub).
2. Render прочитает `render.yaml` и попросит заполнить секреты:
   - `STRAZH_OWNER_PASSWORD` — свой пароль владельца, не короче 12 символов;
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_ALLOWED_USERS` — как в локальном `.env`, или оставьте пустыми;
   - `ANTHROPIC_API_KEY` — по желанию.
   `STRAZH_SECRET_KEY` и `TELEGRAM_WEBHOOK_SECRET` Render сгенерирует сам.
3. Нажмите Apply. Сборка идёт 3–5 минут, адрес вида `https://strazh-invest.onrender.com` появится в панели сервиса.

### Скриптом

Нужен ключ API Render (dashboard.render.com → Account Settings → API Keys).

```bash
RENDER_API_KEY=... .venv/bin/python scripts/deploy_render.py https://github.com/<user>/<repo>
```

Скрипт создаёт сервис `strazh-invest` из `Dockerfile` (Франкфурт, проверка `/healthz`), задаёт переменные, запускает
сборку и ждёт, пока сайт ответит. Пароль владельца он генерирует сам и кладёт в `deploy/owner_password.txt` (права 600,
каталог не попадает в git). Telegram и `ANTHROPIC_API_KEY` скрипт берёт из `.env`, значения не печатает.

Тот же сервис можно создать вручную через Blueprint: `render.yaml` в корне, секреты заполняются в панели Render.

| Переменная | Значение на сайте |
|---|---|
| `STRAZH_MODE` | `public` |
| `STRAZH_OWNER_PASSWORD` | пароль владельца, не короче 12 символов |
| `STRAZH_SECRET_KEY` | ключ подписи cookie владельца; без него ключ случайный и вход слетает при перезапуске |
| `STRAZH_PUBLIC_HOST` | домен сайта; на Render берётся из `RENDER_EXTERNAL_HOSTNAME` сам |
| `STRAZH_MAX_ROOMS` | потолок комнат посетителей, по умолчанию 50 |
| `STRAZH_LLM_HOURLY_LIMIT` | общий бюджет запросов к модели в час, по умолчанию 300 |
| `TELEGRAM_MODE` | `webhook`: Telegram сам присылает сообщения на `/telegram/hook` |
| `TELEGRAM_WEBHOOK_SECRET` | секрет вебхука, не короче 24 символов |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_ALLOWED_USERS` | как локально; без пароля владельца Telegram на сайте не включится |
| `ANTHROPIC_API_KEY` | необязательно; без него шаблоны |

## Что знать о бесплатном тарифе

- **Засыпание.** После 15 минут без запросов сервис засыпает, первое открытие длится около минуты. Перед показом жюри
  откройте сайт заранее. Сообщение в Telegram тоже будит сервис.
- **Нет постоянного диска.** Комнаты посетителей живут в памяти, база владельца — на временном диске: после перезапуска
  или новой сборки всё начинается с чистого листа. Для учебного стенда это нормально.
- **0,1 процессора и 512 МБ памяти.** Цикл симуляции занимает не больше половины процессора, тело запроса ограничено
  16 КБ, комнаты и запросы к модели ограничены.

## Telegram: только один экземпляр

Один токен бота нельзя одновременно опрашивать с двух машин. Когда сайт поставил вебхук, локальный контейнер с тем же
токеном получает от Telegram отказ 409 на опрос и показывает «Telegram: нет связи»; сайт при этом работает. Вебхук
локальный контейнер не снимает. Чтобы вернуть бота на свой компьютер, остановите сайт и снимите вебхук:
`curl "https://api.telegram.org/bot<токен>/deleteWebhook"`. Проще завести второго бота для локального стенда.

## Защита публичного режима

Сервер не запустится в публичном режиме без домена, с коротким паролем, коротким секретом вебхука или с Telegram без
пароля владельца. Остальное описано в [README](../README.md#безопасность) и в [отчёте красного тима](review/adversarial.md).
Ограничения по адресу посетителя только вежливые: адрес берётся из `X-Forwarded-For` и подделывается. От перебора
пароля защищает общий лимит попыток входа, от захвата всех комнат — вытеснение комнат, которые никто не открыл.
